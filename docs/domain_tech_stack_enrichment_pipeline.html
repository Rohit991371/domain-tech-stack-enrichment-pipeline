System Design Traps
The Three Production Traps & Solutions
Slide 04 / 12
1. Timing Trap

Trap: HTTP Archive tables are dated the 1st of the month but don't land until the 3rd week.

Engineering Solution

`arrival_check.py` executes a live row-count probe before unblocking extraction.

2. Grain Trap

Trap: HTTP Archive stores 1 row/origin (`subdomain.site.com`), but downstream needs 1 row/domain.

Engineering Solution

PSL-aware normalize + union aggregation across all origins for that domain.

3. Cost Trap

Trap: Raw tables are 100+ TB. Two unpruned columns alone scan multiple Terabytes.

Engineering Solution

Mandatory Dry-Run Gate, strict column allowlist, and `maximum_bytes_billed` ceiling.

Data Modeling & Normalization
The Grain-Trap Decision: Union Over Selection
Slide 06 / 12
The Real-World Subdomain Problem

Origin A: `example.com` → [WordPress, Cloudflare]

Origin B: `shop.example.com` → [Shopify, Stripe]

Origin C: `blog.example.com` → [Ghost, Disqus]

  • Naive Approach: Picking only apex or highest-traffic origin drops Shopify and Stripe.
  • Business Impact: Sales rep searching for "Companies on Shopify" misses `example.com` completely.
Our Rule: PSL-Aware Union Rollup
  • Public Suffix List (PSL): Correctly groups `co.uk` and `com.au` without mangling root domains.
  • Set Union: All unique technologies detected across all subdomains roll into the parent domain.
  • Explicit Trade-off: We preserve complete feature adoption signals at the expense of origin-level granularity (subdomain attribution).

Structural Guardrails (Not Habits)
  • Column Allowlist: Never execute `SELECT *`. Avoid multi-TB JSON dumps.
  • Mandatory Dry-Runs: Every run queries API dry-run for bytes scanned.
  • Hard Bytes Ceiling: `maximum_bytes_billed` set as query parameter.
  • Anti-Pattern Rejected: SQL `LIMIT` is never used as cost control (scans full column).
Historical Backfill Economics
  • 36-Month Full Backfill: ~$10–$15 one-time BigQuery scan cost.
  • 12-Month Recommendation: Recommended on tech relevance grounds (older tech data is stale), not because of query cost.

AI Strategy & Architecture
AI-Native: The Decision Not to Use an LLM in v1
Slide 11 / 12
Why LLMs Were Excluded from v1 Core
  • Structured Input: Source data is already categorized by Wappalyzer signatures (`technology` + `category`).
  • Strict Determinism: Asking "Does this domain run Shopify?" requires binary precision, not language model hallucinations.
  • Cost Math: LLM inference across 15M records would be 100x the entire data warehouse bill for minimal added value.
Where LLMs Add Value (v2 Scope)
  • Migration-Intent Reasoning: Analyzing multi-month signal drift to score enterprise migration probability.
  • Custom Category Clustering: Grouping proprietary tech stacks where no Wappalyzer tag exists.
  • Strict v2 AI Architecture: Will require versioned prompts, evals dataset, and latency tracing.
